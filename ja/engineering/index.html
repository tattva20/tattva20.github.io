エンジニアリング

エンジニアリングの章

技芸としてのソフトウェア・アーキテクチャ。子どものころのメガドライブに載っていたヤマハ YM2612 チップから、今日出荷している本番環境の iOS システムまで。行動原理はひとつ、オシレーターから積み上げること。

ソフトウェアへの帰還

2016 年にターンテーブルが静かになったとき、私は六歳のころからそばにあった愛へと戻りました。コンピューターです。ターンテーブルに触れるずっと前、1984 年から、パソコンとゲーム機の熱心なユーザーでした。十六年を音楽に捧げたあと、ソフトウェアは再び手に取られるのを待っていました。そして私は、持てるすべてでそれを手に取りました。

帰還の始まり

最初のきっかけは、とても個人的な思いつきでした。Tattva Music のアプリをつくりたかったのです。その小さな野心が私を Xcode に連れ戻し、次に Clean Architecture の本へ、そして独学のマラソンへと導きました。学士号、ソフトウェア工学の修士号、そして Caio と Mike による厳しい Essential Developer プログラム。今はリード・モバイル・アーキテクトとして、iOS、React Native、Android でコードを出荷しています。

技芸としてのアーキテクチャ

私はソフトウェア・アーキテクチャと、その背後にある思想に、遠慮なく情熱を注いでいます。コードをどう配置するかは、セットや文章をどう組み立てるかと同じくらい、その人について多くを語ります。私の考え方とつくり方を形づくってきた方法論は次のとおりです。

  • Clean Architecture — 明確な境界、依存性の逆転、方針は決して詳細に依存してはならないという原則。
  • SOLID 原則 — 保守しやすいオブジェクト指向設計の五つの柱。
  • テスト駆動開発（TDD） — テストに設計を彫らせる。レッド・グリーン・リファクタリングを規律として。
  • The Composable Architecture（TCA） — 状態、副作用、合成のための最先端の Swift フレームワーク。

これらすべての実践的なデモンストレーションが、オープンソース・プロジェクト StreamingVideoApp です。100% テストファーストで書かれた本番品質の iOS 動画ストリーミングのコードベースで、Clean Architecture の層、依存性の拒否、ステートマシン、リアクティブ・プログラミング、アダプティブ・ストリーミングのパターンを文書化しています。いろいろな意味で、私のエンジニアリングのマニフェストです。

好みではなくデータで判断したいときは、書いて確かめます。たとえば Swift 対 Java：計算ベンチマークによる性能の直接比較（英語）。そして、エンジニアリングの判断を手放さずに AI と働く方法は、連載 Combined Force にまとめています。

AI に増幅された、マルチプラットフォームの思考

かつてはひとつのプラットフォームの専門性だったものが、AI の時代にはマルチプラットフォームの流暢さになりました。Swift、SwiftUI、UIKit、Clean Architecture という iOS の深い知識を土台に、私は意図的に React Native と Android へと領域を広げてきました。AI は近道ではなく、力を何倍にもする道具として使っています。すべての行を自分でレビューします。アーキテクチャの美意識を常に中心に置きます。その結果が、今の業界が評価するクロスプラットフォームの多才さです。

iOS、Android、React Native のエンジニア職の技術面接も担当し、ときにはモバイル・セキュリティ職の面接も行います。三つのプラットフォームにわたって人材を評価すること自体が、アーキテクチャの視点を鍛える訓練になっています。

コードと音楽が出会う場所 — tattva20 の GitHub

github.com/tattva20 のリポジトリは、アルゴリズムを磨く実験室です。三つのエンジニアリングのパラダイムが、音の仕事の三つの次元にほぼ一対一で対応しています。コードと音楽が、頭の中の同じオペレーティング・システムの上で動いているようなものです。

  • FM 音源 — メガドライブのヤマハ YM2612 チップに着想を得て Swift で書いた四オペレーター FM シンセサイザー VampireSynth は、デジタル・オシレーター、オーディオ・バッファ、リアルタイム DSP への確かな理解を求めます。同じ数学的な規律が、Tattva 時代の金属的な音色、インダストリアルなサブベース、サイバーパンクな質感を生み出しました。
  • 宣言的なリアクティビティ — Clean Architecture と SwiftUI でつくった WeatherApp や EssentialFeed の課題は、「状態が変われば、インターフェースが反応する」という原理を体現しています。同じ論理がステップ・シーケンサーやライブのモジュレーションを動かします。マスター・クロックがフィルターやエンベロープを通してリアクティブな信号を送り出すのです。
  • ストリームとゼロ・レイテンシー — StreamingVideoApp（Swift）と、そのバックエンド streaming-videos-api（JavaScript）は、注意深いメモリ管理、並行処理、バッファの規律を求めます。同じ技術が、途切れなく続く長いプログレッシブな DJ セットを生み出します。

三つすべてを貫く行動原理はひとつです。プリセットも近道もなし。オシレーターから積み上げるほうが好きなのです。

いつまでもコンピューター少年

大人のアーキテクチャの真面目さの下には、今も画面の前で目を見張る六歳の子どもがいます。私はヴィンテージのコンピューターとゲーム機を生涯愛し続けています。メガドライブと Commodore Amiga は永遠のお気に入りです。コンピューターに何ができるかを知る前に、コンピューターがどう感じられるものかを教えてくれた機械たちです。

ほかのどの本よりも、エンジニアの中の人間として「見てもらえた」と感じさせてくれたのは、Vikram Chandra の Geek Sublime です。コード、美、サンスクリット文法、プログラマーの内面をめぐる思索の書で、まるで著者が世界の向こうから手を伸ばし、私のために書いてくれたかのように感じました。
